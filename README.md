# Инструкции для Claude

Читать перед любой записью или ответом на вопрос по данным.

## Общие правила

1. **Дата и время — только из `date`.** Перед каждой записью выполнять `date +"%Y-%m-%dT%H:%M %z"`.
   Дата из контекста разговора устаревает; на этом уже была ошибка с записью на чужой день.
   Если пользователь называет время без даты — сверить с текущим: «в 22:00» после полуночи
   означает вчерашний день.
2. **Не выдумывать данные.** Нет времени приёма — спросить или поставить интервал «в течение дня»
   и пометить это. Нет веса продукта — спросить, если разница существенная (больше ~100 ккал).
3. **Единицы:** ккал, граммы для Б/Ж/У, миллиграммы для натрия, миллилитры для жидкости,
   килограммы для веса, сантиметры для роста.
4. **Итоги пересчитывать** при каждом добавлении записи в день.
5. **Файл месяца** создавать по шаблону существующего, дни идут по возрастанию.

## Оценка питания

- **По фотографии — только макросы:** калории, белки, жиры, углеводы. Микронутриенты на глаз
  оценивать бессмысленно, их не писать.
- **Натрий, сахар, клетчатку** указывать только когда цифра с этикетки или из базы продуктов.
  Не додумывать по типовым значениям — это уже приводило к противоречию.
- **Сырой или готовый вес** уточнять для мяса и круп: разница до 30%.
- **Масло при жарке** — главный источник разброса: столовая ложка это 90 ккал и 10 г жиров.
  Указывать допущение явно.
- Оценку давать таблицей по компонентам, затем итог и диапазон погрешности.

## Зеркалирование в Google Health

Копию каждой записи о питании и жидкости отправлять через MCP-инструменты форка
`/Users/user/projects/google-health-mcp`:

- `log_nutrition` — еда, поля `food_name`, `meal_type`, `start_time`, `end_time`, `nutrients`;
- `log_hydration` — жидкость в миллилитрах или литрах.

Обязательно `dry_run: false` и `explicit_user_intent: true`, иначе запись не уйдёт.

**Записи в Google Health не редактируются.** Исправление = удалить и создать заново:
`batchDeleteDataPoints(dataType, names)` в `dist/services/google-health-client.js`.
Поэтому цифры уточнять до отправки, а не после.

Вес в Google Health не пишется: нужен скоуп `health_metrics_and_measurements.writeonly`,
сейчас выдан только `nutrition.writeonly`.

Алкоголь в гидратацию не засчитывается — он диуретик. Объём безалкогольных напитков
(вода, энергетики, чай) засчитывается.

## Синхронизация с Fitbit

```bash
node /Users/user/health/sync.mjs [дней]
```

Забирает из Google Health сон, пульс покоя, HRV, SpO2, дыхание, тренировки, шаги и
суточный расход, обновляет `activity.md`, `recovery.md` и раздел Fitbit в `training.md`.

Пишет **только** между маркерами `<!-- fitbit:start -->` и `<!-- fitbit:end -->` —
ручные заметки в тех же файлах не затрагиваются. Запускать перед разбором данных за период.

Ограничения, на которые уже наступали: у `total-calories` роллап не глубже 14 дней,
`floors` и `total-calories` не читаются списком — только роллапом. Пульс покоя с пометкой
`ONLY_WITH_AWAKE_DATA` завышен: часы не видели сон, с другими днями не сравнивать.

## Ответы на вопросы

- Считать по таблицам этой базы, не по памяти о разговоре.
- Всегда называть, на скольких днях основан вывод. Два дня — это не тренд.
- Разделять факты и оценки: «записано» против «оценено по фото».
- Не давать медицинских заключений. Диапазоны и общие принципы — да, диагнозы и лечение — нет.
